## 1. 요약

r/politicalscience 에서 "언론의 편향 보도와 어그로성 기사 때문에 데이터 신뢰도가 낮다" 는 지적을 받았다. 정치학·커뮤니케이션학·전산언어학 논문을 조사해 보정 알고리즘 다섯 개를 설계하고, 그중 넷을 적용했다.

가장 큰 변화는 관계를 정하는 단위다. 예전에는 **기사 하나가 관계 하나를 통째로 결정**했다. 지금은 기사 단위 판정이 근거 로그에 쌓이고, 관계는 그 **전체를 집계한 결과**다. 이것이 없으면 나머지 보정은 계산 자체가 불가능하다.

작업 중 추출기에서 두 가지 결함을 발견했다. 대칭 가설이 명백한 갈등을 임계값 미달로 버리고 있었고, 중복 제거 코드가 실제로는 아무 일도 하지 않고 있었다.

테스트 103개가 통과한다.

## 2. 무엇이 문제였나

| 문제 | 증상 |
|---|---|
| 엣지 덮어쓰기 | `add_edge` 가 `dict.update` 로 병합해, 같은 쌍의 마지막 기사가 앞의 전부를 지웠다. 기사 수·언론사·시간이 남지 않았다 |
| 언론사 미저장 | `press` 를 긁으면서 엣지에는 넣지 않아, 어느 진영이 보도했는지 알 수 없었다 |
| 대칭 가설 | "서로 적대적인 관계이다" 는 상호 상태를 주장한다. 일방적 비판 문장은 이를 함의하지 않아 버려졌다 |
| 기사당 최댓값 채택 | 긴 기사 어딘가의 자극적인 문장 하나가 기사 전체를 대표했다 |
| 죽은 중복 제거 | `seen_titles`/`seen_contents` 에 `add` 를 하지 않아 두 줄이 동작하지 않았다 |
| 허구의 방향 | `source` 가 발화 주체가 아니라 가나다순으로 앞선 이름인데 화살표를 그렸다 |
| 조작된 샘플 관계 | 임포터가 근거 없는 관계 5건을 넣었다. 척도마저 달랐다(샘플 0~100, 실제 0~1) |
| DCP 무효 | 동맹 문맥을 `localhost` 에서 가져와 운영에서 늘 실패했다. 동맹 정의가 "같은 정당" 이라 정파 구조를 증폭했다 |

### 3.0 관측 로그 (선행 조건)

기사 하나의 판정 하나가 `edge_observations` 한 행이다. `(pair_key, url)` 이 유니크라 재수집해도 표본이 부풀지 않는다. 표본이 부풀면 신뢰도가 실제보다 높게 나온다.

엣지는 파이프라인 끝에서 쌍마다 한 번씩만 쓴다. `/api/edge` 는 호불호 엣지를 쓸 때 같은 쌍의 나머지 감정 엣지를 지운다. 예전에는 우호와 갈등이 서로 다른 행이라 같은 두 사람 사이에 동시에 존재할 수 있었다.

### 3.1 사건 단위 중복 제거 — 알고리즘 5(a)

통신사 전재는 편집 판단 한 번이 여러 URL 로 퍼진 것이다. 본문 앞 1500자의 63비트 SimHash(문자 4-그램)로 묶어 클러스터 하나를 관측 한 건으로 센다. 어절 shingle 은 조사와 띄어쓰기가 흔들리는 한국어에서 전재본끼리도 크게 벌어져 쓸 수 없었다.

여기에 "정규화한 제목이 같으면 같은 사건" 규칙을 더했다. 전재는 제목을 두고 본문만 잘라 싣는 경우가 흔하다. 클러스터링은 전역이 아니라 **쌍 단위**로 한다. 같은 두 사람을 함께 언급한 기사끼리만 비교하면 되므로 비교 대상이 적다.

### 3.2 진영 교차 검증 — 알고리즘 2

갈등 보도가 한 진영에서만 나왔다면 사건이 아니라 공격 선택일 수 있다. 진영을 잡음 섞인 관측자로 보고 합친다.

```
진영 c 에 대해
    s_c = 현재 극성을 지지하는 사건 수
    n_c = 그 진영의 전체 사건 수
    r_c = 0.7 · (1 − 0.5^s_c) · (s_c / n_c)
conf = 1 − Π_c (1 − r_c)
κ    = 현재 극성을 보도한 진영 수 / 3
표시 무게 = |최근 논조| · (0.5 + 0.5·κ)
```

계획 단계의 수식 `1 − Π(1 − q_c)` 는 쓸 수 없어 바꿨다. 한 진영이 만장일치면 `q=1` 이라 곱이 0이 되어 `conf=1` 이 나온다. **한 진영만 보도해도 신뢰도가 최대**가 되어 교차 검증 목적과 정반대다.

여러 진영에 걸친 클러스터는 각 진영에 세지 않고 중도(통신)로 접는다. 여러 진영이 같은 원문을 실은 것은 각자의 편집 판단이 아니라 통신사 한 곳의 판단이기 때문이다. 이 규칙이 없으면 전재만으로 교차 검증이 항상 통과한다.

### 3.3 시간 감쇠 — 알고리즘 5(c)

```
w_time = 0.5 ^ (age_days / 45)
score_recent     = Σ w_time·w_a·y / Σ w_time·w_a     # 화면 굵기의 근거
score_cumulative = Σ w_a·y / Σ w_a                   # 감쇠 없는 이력
```

일 단위 EWMA 대신 반감기 지수 감쇠를 썼다. 형태는 같으면서 배치 재계산에 강하다. 관측이 없는 날을 건너뛰어도 결과가 같다.

반감기 45일은 국회 회기가 분기로 돌아가는 것을 보고 그 절반으로 잡았다. 저장소의 설계 메모(`.refs`)가 제안한 EWMA α 0.1~0.3 은 일 단위로 환산하면 반감기 2~7일이라 정치 관계에는 지나치게 빠르다.

`n_observations`, `n_clusters`, `first_seen`, `last_seen`, `peak_score` 를 함께 저장해 "충돌 이력" 뷰의 재료를 남겼다.

### 3.4 발화 주체 귀속 — 알고리즘 4

창마다 방향형 가설 네 개(A→B 반대/지지, B→A 반대/지지)를 묻는다. 각 판정은 근거 문장이 직접 인용인지, 간접 인용인지, 기자 서술인지와 추측성 표현이 있는지를 함께 기록한다.

```
무게 = 직접 인용 1.0 / 간접 인용 0.7 / 기자 서술 0.3
       추측성이면 × 0.5
기사 점수 = 상위 3개 창의 가중 평균 (기존의 단일 최댓값 대체)
```

정치인이 실제로 한 말과 기자가 붙인 대립 구도는 다른 정보다. 유재광·오경수(2012)는 신문이 같은 정치인 발언을 자사 프레임에 맞춰 골라 싣는다는 것을 보였다.

**앵커 규칙**: 창 안에 정치인이 셋 이상이면 두 사람이 같은 문장에 나올 때만 인정한다. 창 안에 두 사람뿐이면 창 전체를 인정한다. 후자는 "나 의원", "이 대표" 같은 축약 지칭을 살리기 위해서다.

**방향 판정**: 절대 점수가 아니라 같은 창에서 두 방향의 차이를 본다. 갈등 문맥에서는 모델이 역방향에도 후하게 답한다. 0.10 이상 차이가 나야 방향을 인정하고, 기사 단위로 모아 한쪽이 두 배를 넘을 때만 엣지에 화살표를 준다.

### 3.5 어그로 할인 — 알고리즘 5(b), 부분 적용

`1/√(기사 내 의원 수)` 만 적용했다. 나열 기사에서 뽑은 쌍은 그 기사의 주제가 아닐 확률이 높다. 화제성에 쓰던 함수를 재사용한다.

클릭베이트 분류기(AI Hub 낚시성 기사 데이터 36만 건)는 미착수다. 제목 단서 사전만으로는 약하고 자의적으로 보이며, 분류기 학습은 나머지를 합친 것보다 큰 작업이다. 이제 관측 로그로 어그로가 실제로 엣지를 왜곡하는지 측정할 수 있으므로, 측정 후 결정한다.

### 3.6 공동발의 그래프 — 알고리즘 3, 코드만

수집기와 집계는 만들었고 DCP 의 동맹 정의를 "같은 정당" 에서 공동발의로 바꿨다. 다만 열린국회정보 OpenAPI 가 등록 키를 요구하는데 **키 발급을 하지 않기로 해서 테이블은 비어 있다.**

따라서 DCP 동맹은 `same_party_fallback` 으로 물러서고, 감사 응답의 `cosponsored_bills` 는 `null` 이다. `null`(확인한 적 없음)과 `0`(확인했고 함께 발의한 적 없음)을 구분한다. 둘을 같이 0으로 돌려주면 협력한 적 없는 사이라고 주장하는 셈이다.

키가 생기면 `ASSEMBLY_API_KEY` 하나로 동작한다. GitHub Actions 단계도 이미 걸려 있다.

## 4. 측정 결과

모든 수치는 이번 작업 중 직접 측정했다. 손으로 쓴 예시 문장 기준이며 라벨링된 코퍼스가 아니다. **벤치마크가 아니라 설계를 바꾼 진단이다.**

### 4.1 대칭 가설이 갈등을 버리고 있었다

전제: "국민의힘 나경원 의원은 더불어민주당 이재명 대표를 겨냥해 비판했다."

| 가설 | 함의 확률 |
|---|---|
| 대칭 (기존) "서로 적대적이거나 비판적인 관계이다" | 0.607 |
| 방향형 "나경원은 이재명을 비판했다" | 0.956 |
| 역방향 "이재명은 나경원을 비판했다" | 0.093 |

임계값이 0.65라 대칭 가설로는 이 갈등이 버려졌다. 엣지가 39개뿐이었던 이유 중 하나로 보인다.

### 4.2 앵커 규칙이 오탐을 걷어낸다

의원 5명이 등장하는 기사 한 건:

| 규칙 | 관계 수 | 오탐 |
|---|---|---|
| 창 안에 두 이름이 있으면 인정 | 10 | 6 |
| 같은 문장에 함께 나올 때만 인정 (셋 이상일 때) | 4 | 0 |

순수 공동 언급 기사("두 사람이 같은 행사에 참석했다")는 이제 관계를 만들지 않는다.

### 4.3 SimHash 임계값

| 경우 | 해밍 거리 (63비트) |
|---|---|
| 같은 원문 + 매체별 저작권·기자 문구 | 5 |
| 같은 원문을 절반으로 자름 | 4 |
| 같은 날 같은 주제, 다른 취재 | 26 |

두 무리가 크게 벌어져 있어 임계값 6으로 잡았다.

### 4.4 신뢰도 곡선

| 근거 | 신뢰도 |
|---|---|
| 보수 1건 | 0.35 |
| 보수 3건 | 0.61 |
| 보수 12건 | 0.70 (상한) |
| 보수 1 + 진보 1 | 0.58 |
| 보수 3 + 진보 3 | 0.85 |

한 진영이 아무리 많이 써도 두 진영이 각자 쓴 것을 넘지 못한다.

### 4.5 전재가 교차 검증을 속이지 못한다

파이프라인 전체를 태운 실측:

| 근거 | 사건 수 | 진영 커버리지 | 신뢰도 |
|---|---|---|---|
| 연합·조선·한겨레가 같은 전재본 3건 | 1 | 1/3 | 0.35 |
| 여기에 경향의 독자 취재 1건 추가 | 2 | 2/3 | 0.58 |

### 4.6 계산 비용

GitHub Actions 러너에는 GPU 가 없으므로 CPU 기준으로 쟀다.

| 항목 | 값 |
|---|---|
| NLI 1회 | 101ms |
| 의원 5명 기사 1건 (가설 2개) | 1.6초 |
| 기사 3000건, 8스레드, 가설 4개 | 약 20분 |

작업 예산이 90분이라 가설을 두 배로 늘리는 것이 가능하다고 판단했다.

## 5. 파이프라인 변화

```
[이전]
기사 → NLI 대칭 가설 2개 → 창별 최댓값
     → 쌍마다 POST /api/edge → dict.update (마지막 기사가 덮어씀)

[현재]
기사 → 문장 분리 → 앵커 규칙 → NLI 방향형 가설 4개 → 상위 3창 가중 평균
     → edge_observations 적재 (press, camp, simhash, holder, evidence_type, 무게)
수집 종료
     → 쌍 단위 SimHash 클러스터링 (전재를 사건 하나로)
     → 사건별 극성·점수 압축
     → 반감기 45일 가중 → score_recent / score_cumulative
     → 진영별 사건 수 → camp_coverage, confidence
     → 방향 판정 → direction, holder, target
     → 쌍마다 POST /api/edge 한 번 (같은 쌍의 다른 감정 엣지는 삭제)
```

빠져 있는 자리는 두 곳이다. 반감기 가중 앞에 알고리즘 1(언론사 논조 기준선)과 3(부정성 역가중)이 들어간다.

## 6. 함께 고친 것

| 항목 | 내용 |
|---|---|
| 샘플 관계 생성 중단 | 임포터가 넣던 근거 없는 관계 5건. 기존 데이터는 `--drop-unsourced` 로만 지운다 |
| DCP 제거 | 운영에서 동작한 적 없고 정파 구조를 증폭했다 |
| 중복 제거 복구 | `seen_titles`/`seen_contents` 에 `add` 누락 |
| 이름 오탐 차단 | 창 안 이름 확인이 단순 부분일치라 김건/김건희 류가 다시 들어올 수 있었다. `find_names` 로 교체 |
| 문장 분리 | `split('.')` 이라 "3.5%" 에서 쪼개졌다. 정규식으로 교체 |
| NLI 라벨 확인 | 주석으로만 "0번이 entailment" 라고 적혀 있었다. 모델 설정에서 읽도록 변경 |
| `dcp_context` 500 | 상대 노드 없는 엣지에서 첨자 접근으로 터졌다 |
| `count` 속성 | 뉴스 파이프라인이 쓴 적 없어 늘 1이었다. 사건 수(`n_clusters`)로 교체 |

## 7. 감사와 검증

편향이 없다고 주장하는 대신 무엇을 근거로 그렸는지 공개하는 쪽을 택했다. 적대적 매체 지각 연구(Vallone 외 1985, Hansen & Kim 2011, 이종혁 2015)에 따르면 관여도 높은 이용자는 어느 쪽이든 편향을 지각한다. 근거를 감추면 신뢰를 얻을 수 없다.

| 수단 | 내용 |
|---|---|
| `GET /api/relations/evidence` | 근거를 그대로 내보낸다. 인증 없는 읽기 전용. 쌍을 지정하면 집계 결과, 사건 묶음, 공동발의 건수, 진영표까지 |
| `GET /api/relations/camps` | 언론사 진영표 공개. 논쟁적인 판단이라 숨기지 않는다 |
| 화면 | 굵기는 교차 검증 무게, 단일 진영은 점선, 화살표는 근거가 방향을 가리킬 때만. 툴팁에 사건 수·기사 수·진영별 사건 수·방향·근거 종류·신뢰도·관측 기간 |
| `scripts/evidence_report.py` | 사건 수 분포, 진영 커버리지, 신뢰도 히스토그램, 전재 비율, 극성 균형, 진영표 미등재 매체 |
| `scripts/coding_sample.py` | 극성×진영 층화 표집, Krippendorff's alpha, 극성별·진영별 정밀도 |

## 8. 현재 상태

**적용 완료**: 관측 로그, 사건 클러스터링, 진영 교차 검증, 시간 감쇠, 발화 주체 귀속, 감사 공개, 검증 도구

**부분 적용**: 어그로 할인(focus weight 만)

**코드만 있고 자료 없음**: 공동발의 그래프(API 키 미발급)

**미적용**: 언론사 논조 기준선, 부정성 역가중 — 둘 다 표본이 더 쌓여야 한다

### 남은 일

1. **손코딩 200건.** reddit 이 지적한 가장 큰 구멍이며 유일하게 사람이 해야 하는 일이다. 도구는 완성됐다.
2. **소급 이관 실행.** 운영 DB 에서 `backfill_edge_observations.py` 를 돌린다. 기존 엣지 중 기사 주소가 있는 것만 관측 1건으로 살아나고 대부분 점선으로 남는다. 손실이 아니라 실제 근거 수준을 드러내는 것이다.
3. **2주 뒤 분포 확인.** `evidence_report.py` 로 최소 사건 수를 2로 올릴지, 진영표에 무엇을 채울지 판단한다.
4. **reddit 게시글의 숫자 채우기.** 초안의 `[ ]` 를 운영 DB 기준으로 채운다.
