## 제목 후보

낚시성 기사를 걸러내겠다고 만든 프로젝트라, 제목이 과하면 첫 댓글이 그 지적이 된다.
그래서 **없는 걸 있다고 하지 않으면서 사람을 멈춰 세우는** 쪽으로 골랐다.
가장 센 후크는 과장이 아니라 실제로 나온 숫자와 버그다.

**1순위 — 발견을 앞세운다 (추천)**

> NLI 가설 한 줄 바꿨더니, 놓치던 정치인 갈등이 잡혔다

> "서로 적대적이다" 라고 물으면 안 된다 — 뉴스에서 정치인 관계 뽑기

정확히 무슨 일이 있었는지 본문에서 바로 확인되는 제목이다. 0.607 → 0.956 이라는
숫자가 뒤를 받쳐 준다.

**2순위 — 버그를 앞세운다**

> 관계 데이터가 매번 마지막 기사 하나로 덮이고 있었다

> 전재 기사 20건은 관측 1건이다 — 뉴스 기반 관계 추출에서 배운 것

개발자가 자기 일처럼 읽는 종류의 실패담이다. 저장 구조 한 줄(`dict.update`)이
집계 기반 보정을 통째로 불가능하게 만들고 있었다는 이야기.

**3순위 — 비판받은 이야기를 앞세운다**

> 레딧에서 "데이터 못 믿겠다" 는 말을 듣고 고친 것들

> 국회의원 관계도를 만들었더니 언론 편향이 그대로 딸려 왔다

**4순위 — 담백하게**

> 국회의원 296명의 관계망을 뉴스에서 자동 추출하는 오픈소스 대시보드

프로젝트 소개로는 이게 가장 정확하다. 후크가 약할 뿐이다.

**피할 것**

- "충격", "역대급", "아무도 몰랐던" 류. 이 프로젝트가 낚시성 기사를 감점 처리한다고
  본문에서 말하는데 제목이 낚시면 그 자체가 반박거리가 된다
- "AI 가 정치인 관계를 분석했다" 처럼 크게 말하기. 사람이 검증한 표본이 없다고
  본문에서 인정하는 상태라 제목과 어긋난다

## 내용

한국어 뉴스에서 국회의원 사이의 갈등·우호 관계를 뽑아 그래프로 그리는 오픈소스를 만들고 있다. Zero-Shot NLI 로 판정하는데, 가설 문장을 이렇게 물었다.

> 이 문맥에서 {A}와 {B}는 서로 적대적이거나 비판적인 관계이다.

- 이게 관계를 조용히 버리고 있었다. 저 문장은 **상호** 상태를 주장하는데, 한쪽이 일방적으로 비판한 문장은 그걸 함의하지 않는다
- "국민의힘 나경원 의원은 더불어민주당 이재명 대표를 겨냥해 비판했다" 라는 교과서적인 갈등 문장에 물어 봤다

| 가설 | 함의 확률 |
| --- | ---: |
| 대칭 (기존) "서로 적대적이거나 비판적인 관계이다" | 0.607 ← 임계값 0.65 미달로 **버려짐** |
| 방향형 "나경원은 이재명을 비판했다" | 0.956 |
| 역방향 "이재명은 나경원을 비판했다" | 0.093 |

- 방향형으로 바꾸니 놓치던 갈등이 잡히고, 덤으로 **방향**까지 생겼다. 그전까지 엣지의 source 는 발화 주체가 아니라 가나다순으로 앞선 이름이었고, 화면의 화살표는 전부 허구였다
- 대신 이번엔 공동 언급이 관계로 둔갑했다. 의원 5명이 나오는 기사 하나에서 창 기준으로 관계 10개가 나왔는데 그중 6개가 서로 아무 말도 하지 않은 쌍이었다. 셋 이상이 섞인 창에서는 같은 문장에 함께 나올 때만 인정하도록 바꾸니 4개만 남고 전부 실제 관계였다

### 무슨 프로젝트인가

- 제22대 국회의원 296명을 하나의 그래프로 보는 대시보드. 누가 누구와 대립하고 협력하는지를 표결 기록이 아니라 **뉴스 본문**에서 추론한다
- 매일 새벽 GitHub Actions 가 네이버 뉴스 정치·경제·사회 섹션과 의원별 검색을 돌고, 위 방식으로 관계를 뽑아 그래프를 갱신한다
- 화제성은 별도로 최근 7일 뉴스 언급과 유튜브 조회수를 합산한다. 관계는 누적, 화제성은 롤링이라 화면에 각각 기간을 표시한다
- MIT 라이선스. 백엔드는 Python/FastAPI/PostgreSQL, 프론트는 React + vis-network([별도 저장소](https://github.com/showjihyun/frontend))

### 진짜 문제는 알고리즘이 아니라 저장 구조였다

- r/politicalscience 에 올렸다가 "편향 보도와 어그로성 기사 때문에 데이터를 믿기 어렵다" 는 지적을 받았다. 맞는 지적이라 정치커뮤니케이션·전산언어학 논문을 뒤져 보정을 다시 설계했는데, 손대 보니 앞이 막혀 있었다
- 엣지 properties 를 `dict.update` 로 병합하고 있었다. 그래서 **같은 두 사람을 다룬 마지막 기사가 앞의 기사 전부를 덮어썼다.** 기사 수도 언론사도 시간도 남지 않았다. 집계 기반 보정은 계산 자체가 불가능했다
- 지금은 기사 단위 판정을 append-only 로 쌓고, 관계는 그 전체를 집계한 결과로만 만든다. 아래 보정은 전부 그 위에 얹힌다

### 넣은 보정

- **사건 단위 중복 제거**: 통신사 전재는 편집 판단 한 번이 여러 URL 로 퍼진 것이다. 본문 SimHash(문자 4-그램, 63비트)로 묶어 한 표로 센다. 어절 shingle 은 조사와 띄어쓰기가 흔들리는 한국어에서 전재본끼리도 크게 벌어져 못 썼다
- **진영 교차 검증**: 보수·중도·진보를 잡음 섞인 관측자로 보고 noisy-OR 로 합친다. 한 진영은 상한 0.7 을 못 넘어서, 물량으로 신뢰를 살 수 없다. 여러 진영에 같은 원문이 실린 클러스터는 통신사 판단이므로 중도로 접는다. 이게 없으면 전재만으로 교차 검증이 항상 통과한다
- **발화 주체 귀속**: 정치인의 직접 인용(1.0), 간접 인용(0.7), 기자 서술(0.3)을 구분해 무게를 달리 준다. 추측성 표현은 절반으로 깎는다
- **시간 감쇠**: 반감기 45일. 최근 논조와 누적 이력을 따로 보관한다

> 위 수치는 손으로 쓴 예시 문장에서 잰 것이다. 라벨링된 코퍼스가 아니므로 벤치마크가 아니라 **설계를 바꾼 진단**으로 봐 달라.

### 근거를 감추지 않는다

- 적대적 매체 지각 연구(Vallone 외 1985)에 따르면 관여도 높은 이용자는 어느 쪽이든 편향을 지각한다. "우리는 편향이 없다" 고 말해 봐야 소용이 없다는 뜻이다. 그래서 근거를 전부 공개하는 쪽을 택했다
- 화면에서 관계선을 누르면 사건 수, 진영별 사건 수, 신뢰도, **근거 기사 목록이 원문 링크와 함께** 열린다. 전재 여러 건이 한 사건으로 묶인 경우 그 사실도 표시한다
- 인증 없는 읽기 전용 API 도 열려 있다

```
GET /api/relations/evidence?a=나경원&b=안철수   # 관계 하나의 근거 전체
GET /api/relations/evidence?limit=200           # 근거 원본 덤프
GET /api/relations/camps                        # 언론사 진영표 공개
```

- 진영 구분은 그 자체로 논쟁적인 판단이라 표를 통째로 공개한다. 모르는 매체는 억지로 배정하지 않고 중도로 둔다

### 화면에서 신뢰도가 보인다

- 선 굵기가 교차 검증을 반영한 무게를 따른다
- **한 진영에서만 보도된 관계는 점선**이다
- 화살표는 근거가 방향을 가리킬 때만 그린다. 서로 주고받은 관계는 화살표가 없다. 예전에는 모든 관계에 화살표가 있었는데, source 가 발화 주체가 아니라 가나다순으로 앞선 이름이라 방향이 전부 허구였다

### 아직 못 한 것

- **사람이 검증한 표본이 없다.** 정밀도·재현율 수치가 없으므로 관계 데이터는 아직 분석 결과가 아니라 예시다. 층화 표집과 Krippendorff's alpha 채점 도구는 만들어 뒀고 남은 건 사람이 코딩하는 일이다. 이게 가장 큰 구멍이다
- **수집원이 포털 한 곳**이다. 언론사 진영은 통제하지만 포털의 편집 선택은 통제하지 못한다
- **언론사별 논조 기준선 보정**을 못 했다. 조선일보가 야당 의원을 비판한 기사와 한겨레가 같은 의원을 비판한 기사는 정보량이 다른데, 이걸 빼려면 언론사×정당 셀마다 표본이 수십 건 필요하다
- **협력의 증거가 부족하다.** 뉴스는 갈등을 싣고 협력은 안 싣는다. 국회 공동발의로 보완하려고 수집기까지 만들었는데 열린국회정보 API 키를 받지 않기로 해서 비어 있다. 키 없이 쓸 방법을 아시는 분 있으면 알려 주시면 좋겠다
- **데이터가 어리다.** 연속 수집은 2026-08-30 부터다

## 짧은 버전 (분량을 줄여야 할 때)

- 뉴스에서 국회의원 사이의 갈등·우호 관계를 뽑는 오픈소스를 만들고 있다. Zero-Shot NLI 로 판정하는데, 가설을 "A와 B는 서로 적대적이다" 라고 물었더니 관계를 조용히 버리고 있었다
- 저 문장은 **상호** 상태를 주장해서, 한쪽이 일방적으로 비판한 문장은 함의하지 않는다. "나경원 의원은 이재명 대표를 겨냥해 비판했다" 에서 대칭 가설 **0.607**(임계값 0.65 미달로 버려짐), 방향형 "나경원은 이재명을 비판했다" **0.956**, 역방향 **0.093**
- 방향형으로 바꾸니 놓치던 갈등이 잡히고 방향까지 생겼다. 대신 공동 언급이 관계로 둔갑해서, 창에 셋 이상 있으면 같은 문장을 요구하도록 바꿨다(관계 10개 중 오탐 6개 → 0개)
- 더 큰 문제는 저장 구조였다. 엣지를 `dict.update` 로 병합해 **마지막 기사가 앞의 전부를 덮어썼다.** 기사 수도 언론사도 안 남아 집계 기반 보정이 불가능했다. 지금은 근거를 append-only 로 쌓고 관계는 그 집계로만 만든다
- 그 위에 통신사 전재 묶기(SimHash), 진영 교차 검증, 반감기 45일을 얹었다. 한 진영은 물량으로 신뢰를 살 수 없다
- 관계선을 누르면 근거 기사가 원문 링크와 함께 열린다. 인증 없는 근거 API 와 언론사 진영표도 공개한다
- 아직 사람이 검증한 표본이 없어서, 관계 데이터는 분석 결과가 아니라 예시로 봐 달라. MIT, 방법론 비판 환영

## 댓글로 나올 만한 질문과 답

**"진영 구분은 누가 정했나"**
`core/media_outlets.py` 에 표로 두고 근거(최창식·임영호 2021 의 신문별 감성지수, KoPolitic 벤치마크의 보수2/중도2/진보2 구성)를 함께 적었다. `/api/relations/camps` 로 통째로 공개한다. 모르는 매체는 중도로 떨어뜨린다. 관측이 쌓이면 이 정적 표를 언론사×정당 논조 기준선 추정으로 대체할 계획이다.

**"NLI 로 한국어 정치 문맥을 제대로 잡나"**
못 잡는 경우가 있다. 그래서 사람이 검증한 표본이 필요하다고 계속 적어 두었다. 지금 할 수 있는 건 근거 문장을 전부 공개해서 각자 판단하게 하는 것뿐이다.

**"갈등이 우호보다 많은 건 편향 아닌가"**
뉴스 가치 연구(Galtung & Ruge 1965, Soroka 2006)는 갈등 우위를 예측한다. 다만 추출기가 부정 표현에 치우쳤을 가능성도 있고, 이 비율만으로는 둘을 구분할 수 없다. 손코딩 표본이 나와야 답할 수 있다.

**"실시간인가"**
아니다. 하루 한 번이다.
